# KU Leuven external validation

## Purpose

This report records the first evaluation of the Smart Study Planner's
academic-risk modelling approach on a real public dataset that was not
generated by this repository. It is an external validation track, not a
replacement for the synthetic Indian-university planner data and not a claim
that the synthetic data has become representative of a particular university.

The source is **Open Data, Private Learners: A De-Identified Dataset for
Learning Analytics Research**, published by KU Leuven on Zenodo. The record
identifies the release as CC BY 4.0 and provides a `dataset.zip` file. The
dataset was prepared from Blackboard LMS and student-information-system data,
was de-identified, and covers two first-year bachelor courses across three
academic years. The source paper describes institutional ethical review and
privacy-preserving preparation. See the [Zenodo record](https://zenodo.org/records/17087849)
and the [Scientific Data description](https://doi.org/10.1038/s41597-026-06821-3).

The downloaded file is kept outside Git and is versioned with DVC. Its
published and locally verified checksum is:

```text
MD5: 9f559e96d91f6a4c447ba41a783ff277
File: data/raw/external/kuleuven/dataset.zip
```

## Why this dataset was selected

The project needs a real-world test that contains both observable learning
behaviour and an academic outcome. The KU Leuven release provides LMS activity
logs and final course-participation outcomes, making it suitable for testing
whether early engagement signals retain useful ranking information in a later
academic year.

It does not contain sleep, break time, screen time, CGPA, or Indian-university
context. Consequently, it cannot validate those synthetic planner attributes.
Those attributes remain development features until an appropriately consented
institutional or behavioural dataset is obtained.

## Files and raw-data structure

The archive contains one participation table and one LMS activity log for each
of the `1819`, `1920`, and `2021` academic-year releases.

### Participation tables

The `*_course_participation.xlsx` tables contain:

| Source column | Meaning in this evaluation | Use |
|---|---|---|
| `COURSE_ID` | Course identifier | Predictor category |
| `USER_ID` | Anonymised learner identifier | Split/audit key only; never a predictor |
| `SCORE_CATEGORY_JANUARY` | January score category | Excluded to avoid unobserved assessment leakage |
| `SCORE_CATEGORY_JUNE` | June score category | Excluded |
| `SCORE_CATEGORY_SEPTEMBER` | September score category | Excluded |
| `SCORE_CATEGORY_FINAL` | Final score category | Excluded; final outcome information |
| `PASSED_FIRST_ATTEMPT` | First-attempt pass indicator | Excluded from this binary target |
| `PASSED` | Final course pass indicator | Target source: `target_risk = 1 - PASSED` |

The loader removes 12 exact duplicate participation keys observed in the
release. It first checks that repeated keys do not have conflicting outcomes;
conflicting labels would stop the pipeline rather than being silently resolved.

### LMS activity logs

The `*_log_activity.csv` tables contain:

| Source column | Meaning in this evaluation | Derived feature |
|---|---|---|
| `ACTION_ID` | Activity-record identifier | Counted as an observed activity |
| `COURSE_ID` | Course associated with the event | Join key |
| `USER_ID` | Anonymised learner identifier | Join key |
| `CONTENT_ID` | Content item involved | Distinct content count |
| `SESSION_ID` | Learning session identifier | Distinct session count |
| `TIMESTAMP` | Event timestamp | Cutoff filtering and active-day count |

## Feature extraction and temporal controls

The unit of analysis is one learner-course-year participation row. The raw
release does not provide a single canonical course-start field. The adapter
therefore uses the first recorded LMS activity for each course and academic
year as the observation anchor. This is a documented operational assumption,
not an observed institutional calendar date.

For each cutoff, only events satisfying

```text
0 <= TIMESTAMP - first_recorded_course_activity <= cutoff_days
```

are aggregated. The predictors are:

- `course_id`;
- `activity_count`;
- `active_day_count`;
- `content_count`;
- `session_count`;
- `mean_daily_activity`;
- `has_activity`.

Final score categories and `PASSED` are never included in the predictor matrix.
Missing activity is represented as zero observed activity, which is different
from imputing a missing academic grade as zero.

## Evaluation design

The experiment is prospective and time ordered:

| Partition | Academic release | Role |
|---|---|---|
| Train | 1819 | Fit preprocessing and candidate models |
| Validation | 1920 | Select the model and operating threshold |
| Locked test | 2021 | One final external evaluation |

The anonymised learner ID is excluded from predictors. The released IDs recur
across years, so this is a same-institution prospective-year test rather than
an unseen-student generalisation test. The result reports the overlap counts
explicitly. A stricter unseen-student study would require a source with cohort
identifiers and sufficient disjoint sample size.

Four baseline models are compared: logistic regression, random forest, extra
trees, and histogram gradient boosting. The model-selection rule is validation
PR-AUC, followed by validation ROC-AUC, balanced accuracy, and F1. The test
set is not used to select the model or threshold.

## Measured results

The results below were generated by:

```powershell
.\.venv\Scripts\python.exe -m pipeline.kuleuven_external_validation `
  --data-path data/raw/external/kuleuven/dataset.zip `
  --metrics-output models/metrics/kuleuven_external_metrics.json `
  --cutoffs-days 30 60 90
```

The partitions contain 1,495 training rows, 1,386 validation rows, and 1,399
locked-test rows. The 2021 test risk count is 510 and the non-risk count is
889. The complete output, including calibration and threshold diagnostics, is
stored in `models/metrics/kuleuven_external_metrics.json`.

| Cutoff | Selected model | Test ROC-AUC | Test PR-AUC | Balanced accuracy | F1 | Test confusion matrix `[[TN, FP], [FN, TP]]` |
|---:|---|---:|---:|---:|---:|---|
| 30 days | Logistic regression | 0.6754 | 0.5408 | 0.5907 | 0.3755 | `[[815, 74], [375, 135]]` |
| 60 days | Logistic regression | 0.6986 | 0.5664 | 0.6247 | 0.4677 | `[[783, 106], [322, 188]]` |
| 90 days | Logistic regression | 0.7207 | 0.6057 | 0.6433 | 0.5089 | `[[769, 120], [295, 215]]` |

The model is selected independently at each cutoff using validation evidence;
the selected result happens to be logistic regression at all three cutoffs.
The increasing discrimination with later cutoffs is consistent with the
availability of more activity evidence, but it also means less time remains
for intervention. It does not prove that a 90-day policy is operationally
better.

## Interpretation and limitations

These results support only the following narrow conclusion: early LMS activity
aggregates contain measurable association with final pass outcomes in this
KU Leuven release under the documented temporal protocol. They do not establish
causal effects, intervention effectiveness, fairness across Indian student
groups, or transferability to the synthetic planner schema.

The principal limitations are:

1. the observation anchor is a first-recorded-activity proxy;
2. the data represents two courses at one institution;
3. anonymised students recur across years, so the test is temporal rather than
   strictly unseen-student;
4. final outcomes are used as labels, so this remains retrospective evaluation;
5. activity logs do not measure sleep, breaks, screen time, wellbeing, or
   planner adherence;
6. the low alert precision at some thresholds shows that a deployment policy
   still requires reviewed intervention capacity, calibration, and prospective
   institutional validation.

The experiment must therefore be described as an external academic-risk
benchmark. It must not be reported as evidence that the synthetic Indian-
university planner or its behavioural features are valid in production.
